| **1–2** | **Need for OOP vs Procedural Programming** | Implemented (Phase 2) | `com.traffic.model` | Real-world entities (cars, roads, traffic lights) are modeled as objects holding their own data and behaviors. | **Q:** Why use OOP for this simulator?<br/>**A:** OOP bundles data and functions into objects, modeling cars and roads cleanly without global variables. |
| **3** | **Data Types and Variables** | Implemented (Phase 2) | `Vehicle.java`, `TrafficSignal.java` | Uses primitive types (`int speed`, `int waitingTime`, `boolean emergencyOverride`, `int timer`). | **Q:** What is the difference between primitive and reference data types?<br/>**A:** Primitive types store raw values; reference types store addresses of objects on the heap. |

| **5** | **Control Flow I: Decision Making (`if-else`, `switch`)** | Implemented (Phase 2) | `TrafficSignal.java`, `Intersection.java` | `if (newColor == SignalColor.GREEN)` sets timer; `if (v.isEmergency())` detects ambulances. | **Q:** When should you use `if-else` vs `switch`?<br/>**A:** Use `switch` for multiple discrete constant values; use `if-else` for complex or range conditions. |

| **8** | **Type Conversion & Wrapper Classes** | Planned (Phase 4) | `ReportService.java` | Parsing numbers from text files (`Integer.parseInt`) and wrapping numeric metrics. | **Q:** What is autoboxing in Java?<br/>**A:** The automatic conversion of primitive types to wrapper classes (e.g. `int` to `Integer`). |
| **9** | **Arrays: Single Dimensional** | Implemented (Phase 2) | `Intersection.java` | Fixed array `Road[] roads = new Road[4]` representing North, East, South, and West approaches. | **Q:** Why use a fixed array `Road[4]` for the intersection?<br/>**A:** A four-way junction has exactly 4 physical approaches, making a fixed-size array fast and memory-efficient. |
| **10** | **Classes & Objects: Declaring and Creating** | Implemented (Phase 2) | `Car.java`, `Main.java` | Creating concrete instances (`Car car1 = new Car("CAR-1", 40, 2);`). | **Q:** What happens in memory when `new` is called?<br/>**A:** Memory is allocated on the heap, instance variables are initialized, and the constructor executes. |
| **12** | **Methods: Declaring and Calling** | Implemented (Phase 2) | All Model Classes | Methods define behaviors: `road.addVehicle(v)`, `signal.tick()`, `signal.switchToGreen()`. | **Q:** What is the difference between instance and static methods?<br/>**A:** Instance methods operate on an object's state; static methods belong to the class itself. |
| **13** | **Constructors: Default and Parameterized** | Implemented (Phase 2) | `Vehicle.java`, `Road.java` | Parameterized constructors (`Car(id, speed, passengers)`) and default/overloaded constructors. | **Q:** Can a constructor return a value?<br/>**A:** No, constructors have no return type, not even `void`. |
| **14** | **Method & Constructor Overloading** | Implemented (Phase 2) | `Car.java`, `Road.java`, `TrafficSignal.java` | `Car(id, speed, passengers)` and `Car(id, speed)` demonstrate constructor overloading. | **Q:** What is constructor overloading?<br/>**A:** Having multiple constructors in the same class with different parameter lists. |
| **15** | **Objects as Parameters & Call by Value** | Implemented (Phase 2) | `Road.java` | Passing `Vehicle` objects into `road.addVehicle(Vehicle v)`. Java passes object references by value. | **Q:** Does Java pass objects by reference?<br/>**A:** No, Java is strictly **call-by-value**. It passes a copy of the reference address by value. |
| **17** | **Returning Objects & Recursion** | Implemented (Phase 2) / Planned (Phase 4) | `Road.java`, `ReportService.java` | Methods returning objects (`road.removeVehicle()`, `road.peekVehicle()`); recursive report tree traversal planned. | **Q:** What is a base condition in recursion?<br/>**A:** The stopping condition that prevents infinite recursive calls. |
| **18** | **Access Control (`public`, `private`, `protected`)** | Implemented (Phase 2) | All Model Classes | `private` variables enforce encapsulation; `public` getters/methods provide safe access. | **Q:** Why keep instance variables `private`?<br/>**A:** To protect data integrity from direct external tampering (Encapsulation). |
| **19** | **`final` Keyword & Garbage Collection** | Implemented (Phase 2) | `Main.java`, `Road.java`, `TrafficSignal.java` | `public static final int DEFAULT_MAX_CAPACITY = 20;` creates immutable class constants. | **Q:** What does `final` mean on a variable?<br/>**A:** It creates a constant whose value cannot be reassigned once initialized. |
| **21** | **Nested and Inner Classes** | Planned (Phase 4) | `ReportService.java` | Helper nested classes for report data formatting and summary statistics. | **Q:** What is an inner class?<br/>**A:** A class defined inside another class that has access to the outer class's members. |
| **22** | **Inheritance Basics (`extends` keyword)** | Implemented (Phase 2) | `Car.java`, `Bike.java`, `Bus.java` | `public class Car extends Vehicle` derives from the base `Vehicle` class. | **Q:** What is the primary benefit of inheritance?<br/>**A:** Code reusability and establishing an *is-a* relationship. |
| **23** | **Access Modifiers in Inheritance** | Implemented (Phase 2) | `Vehicle.java`, `Car.java` | Subclasses access parent state via `getId()` and `getSpeed()` while fields remain `private`. | **Q:** Can a subclass access private fields of its parent?<br/>**A:** No, private fields are only accessible inside the parent class itself. |
| **24** | **`super` Keyword** | Implemented (Phase 2) | `Car.java`, `Ambulance.java` | Calling the parent constructor using `super(id, speed);`. | **Q:** Where must `super()` be placed in a constructor?<br/>**A:** It must be the very first statement inside the child constructor. |
| **26** | **Multilevel Hierarchy** | Implemented (Phase 2) | `Vehicle` &rarr; `EmergencyVehicle` &rarr; `Ambulance` | 3-tier chain: `Vehicle` (Level 1) &rarr; `EmergencyVehicle` (Level 2) &rarr; `Ambulance` (Level 3). | **Q:** What is multilevel inheritance?<br/>**A:** A chain of inheritance where a class inherits from a derived class (Grandparent &rarr; Parent &rarr; Child). |
| **27** | **Method Overriding (`@Override`)** | Implemented (Phase 2) | `Car.java`, `Ambulance.java` | Child classes provide unique implementations of `displayInfo()` and `calculatePriority()`. | **Q:** What is method overriding?<br/>**A:** A subclass providing its own specific implementation of a method defined in its superclass. |
| **28** | **Polymorphism: Dynamic Method Dispatch** | Implemented (Phase 2) | `Road.java`, `ModelTest.java` | Invoking `v.calculatePriority()` on a `Vehicle` reference resolves to the child's version at runtime. | **Q:** What is dynamic method dispatch?<br/>**A:** Resolving the call to an overridden method at runtime based on the actual object on the heap. |
| **30** | **Abstract Classes & Interfaces** | Implemented (Phase 2) | `Vehicle.java` (abstract), `EmergencyCapable.java` (interface) | `abstract class Vehicle` sets a template; `interface EmergencyCapable` specifies siren operations. | **Q:** Why make `EmergencyCapable` an interface?<br/>**A:** To separate emergency capabilities so regular vehicles (cars, bikes) are not forced to have sirens. |
| **31** | **Inheritance vs. Composition ("is-a" vs "has-a")** | Implemented (Phase 2) | `Road.java`, `Intersection.java` | `Car` *is-a* `Vehicle` (Inheritance); `Road` *has-a* `TrafficSignal`, and `Intersection` *has-a* `Road[]` (Composition). | **Q:** Why prefer composition for Road and TrafficSignal?<br/>**A:** A road is not a type of signal; it contains and controls a signal. |

| **36** | **Exception Types (Checked vs Unchecked)** | Implemented (Phase 2 & 4) | `ReportException.java` (Checked), `IllegalArgumentException` (Unchecked) | Custom `ReportException extends Exception` (Checked) forces compile-time handling; `IllegalArgumentException` (Unchecked) guards runtime invariants. | **Q:** What is the difference between checked and unchecked exceptions?<br/>**A:** Checked exceptions are verified by the compiler and must be declared or caught; unchecked exceptions occur at runtime. |
| **37** | **`try`, `catch`, `finally` Construct** | Implemented (Phase 4) | `ReportService.java`, `Main.java` | Safely closes file streams inside `finally` blocks, guaranteeing cleanup even when I/O errors occur. | **Q:** When does `finally` execute?<br/>**A:** Always, whether an exception was thrown or caught (ensuring guaranteed resource cleanup). |
| **38** | **`throw` & `throws` Keywords & Custom Exceptions** | Implemented (Phase 4) | `ReportException.java`, `ReportService.java` | Custom exception `ReportException` created with constructor chaining; declared with `throws ReportException` and thrown with `throw`. | **Q:** How do you create a custom checked exception?<br/>**A:** Create a class extending `java.lang.Exception` and call `super(message)` in its constructor. |
| **40** | **Multithreading: Process vs Thread** | Implemented (Phase 5) | `SimulationController.java` | Background worker thread executes simulation ticks independently without blocking the caller. | **Q:** Why does the simulation need multithreading?<br/>**A:** So the continuous simulation tick loop does not freeze user interaction or the future UI. |
| **41** | **Creating Threads: `Runnable` vs `Thread`** | Implemented (Phase 5) | `SimulationController.java` | `SimulationController implements Runnable` and passes itself to `new Thread(this, name)`. | **Q:** Why implement `Runnable` instead of extending `Thread`?<br/>**A:** Java does not support multiple class inheritance; implementing `Runnable` keeps classes flexible and decouples task from thread. |
| **42** | **Thread Lifecycle & `start()` vs `run()`** | Implemented (Phase 5) | `SimulationController.java` | Uses `workerThread.start()` to launch a separate call stack. Uses `Thread.sleep(tickDelayMs)` for tick delays. | **Q:** What happens if you call `run()` instead of `start()`?<br/>**A:** Calling `run()` executes sequentially on the current thread; `start()` allocates a new call stack and spawns an OS thread. |
| **43** | **Thread Priorities & `join()`** | Implemented (Phase 5) | `SimulationController.java` | `controller.join()` and `controller.join(millis)` wait for the background worker thread to die cleanly. | **Q:** What does `join()` do?<br/>**A:** Suspends the calling thread until the target thread finishes execution and enters the `TERMINATED` state. |
| **45** | **Synchronization (`synchronized` methods/blocks)** | Implemented (Phase 5) | `SimulationController.java` | `synchronized` lifecycle methods and `synchronized (pauseLock)` protect shared state during thread transitions. | **Q:** What is the purpose of synchronization?<br/>**A:** To ensure mutual exclusion and prevent race conditions when multiple threads access shared mutable state. |
| **46** | **Inter-thread Communication: `wait()`, `notifyAll()`** | Implemented (Phase 5) | `SimulationController.java` | `pauseLock.wait()` suspends the worker thread with 0% CPU consumption; `pauseLock.notifyAll()` wakes it up on resume. | **Q:** Why must `wait()` and `notify()` be inside a synchronized block?<br/>**A:** They require ownership of the object's monitor lock to prevent lost-wakeup race conditions. |
| **47** | **Suspending, Resuming, and Stopping Threads Safely** | Implemented (Phase 5) | `SimulationController.java` | Uses `volatile boolean running` and `volatile boolean paused` flags with `interrupt()` instead of deprecated `Thread.stop()`. | **Q:** Why is `Thread.stop()` deprecated?<br/>**A:** It abruptly kills threads while they hold locks, leaving shared data structures corrupted and inconsistent. |
| **48** | **Java Swing GUI & Event-Driven Architecture** | Implemented (Phase 6) | `MainFrame.java`, `IntersectionPanel.java` | Custom 2D canvas drawing (`paintComponent`), Swing components (`JFrame`, `JPanel`, `JButton`, `JSlider`), and EDT event timer. | **Q:** Why must GUI updates happen only on the Event Dispatch Thread?<br/>**A:** Swing is not thread-safe; modifying UI components concurrently from background threads causes screen flickering, race conditions, and deadlocks. |
